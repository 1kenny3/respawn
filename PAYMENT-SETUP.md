# Т-Касса: подключение RESPAWN

Подготовлены серверные Init/GetState, проверка подписи уведомлений, хранение заказов в D1, расчёт суммы по серверному каталогу и платёжный экран. Реальный приём денег выключен: у владельца пока нет терминала Т-Кассы. Текущие цены каталога утверждены владельцем 28 октября 2026.

## До включения

1. Зарегистрировать магазин в Т-Кассе, передать реальные сведения продавца и согласовать ассортимент с банком. Получить тестовый терминал, пройти проверку, затем получить рабочий.
2. В кабинете эквайринга включить готовую платёжную форму и СБП. Выбор конкретного банка, QR и переход в банковское приложение выполняет форма Т-Банка. Сайт не конструирует банковские ссылки и не обещает веб-банк у каждого банка. Карты также оплачиваются на форме банка.
3. Согласовать реальные условия выдачи валюты, контакты поддержки и оферту. Сейчас автоматическая выдача товаров не реализована.
4. Определить фискализацию, налоговый режим, ставку НДС и предмет расчёта с владельцем/бухгалтером; не копировать случайные значения.
5. Сейчас сайт приватный. Уведомление от Т-Банка не пройдёт авторизацию Sites. Прежде чем включать оплату, владелец должен отдельно разрешить публичный доступ или выбрать публичное размещение платёжного backend. Не передавать банку токен доступа ко всему приватному сайту.
6. Адрес уведомлений: https://pixel-market-kenny.jollyfrost8.chatgpt.site/api/payments/notify. В кабинете терминала включить HTTP(S)-уведомления. Успешная страница сама по себе не подтверждает оплату — используется только серверная проверка.

## Серверные переменные Sites

Добавлять через защищённые настройки окружения Sites, затем развернуть новую версию. Не записывать пароль в чат, исходники, .openai/hosting.json, публичную папку или браузер.

- `TBANK_TERMINAL_KEY` — идентификатор нужного терминала.
- `TBANK_PASSWORD` — пароль терминала, secret.
- `TBANK_MODE` — `test` либо `live`. Метка не превращает рабочий терминал в тестовый: использовать именно тестовый терминал для тестирования.
- `TBANK_ENABLED` — `true` только после остальных проверок.
- `TBANK_CALLBACK_READY` — `true` после проверки доступности уведомлений извне.
- `TBANK_RECEIPT_MODE` — `enabled` при отправке чека через эквайринг либо `not_required` только после подтверждения владельцем применимости такого режима.
- `TBANK_TAXATION`, `TBANK_TAX`, `TBANK_PAYMENT_OBJECT` — согласованные значения для чека. При `enabled` все три обязательны.

Ограничение: checkout пока требует вход через Sites. На публичном сайте нужно сохранить этот вход или реализовать отдельную защищённую идентификацию покупателя. Самостоятельно доступ сайта не менялся.

Проверки: `node tests/payments.mjs`, `node tests/calculator.cjs`. Серверный каталог — `public/products.json`; цены клиентских карточек в `public/app.js` должны совпадать с ним. Backend игнорирует цены, отправленные браузером.

Состояние `INIT_UNKNOWN` означает неоднозначный результат Init: не создавать повторное списание, сверить заказ в кабинете банка. Один requestId создаёт один заказ; при изменении корзины браузер генерирует новый.
